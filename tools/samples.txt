To solve this problem, we need to determine the total money Grandma Laura should have earned by selling apples to her buyers, considering that each buyer might have received an additional half apple as a gift if the number of apples was odd at the time of purchase. 

### Approach
1. **Reverse Process Analysis**: Instead of starting from the initial number of apples (which is unknown), we work backwards from the end where Grandma has zero apples left. This helps us avoid the complexity of guessing the initial number of apples.
2. **Reversed Buyer Processing**: By processing each buyer in reverse order, we can reconstruct the number of apples Grandma had before each sale. This allows us to compute the total money earned correctly.
3. **Mathematical Calculation**: For each buyer, depending on whether they received a half apple as a gift or not, we compute the number of apples they bought and the corresponding money earned. The cost per apple is given, and since it's even, we handle fractional payments using integer arithmetic to avoid precision issues.

### Solution Code
```python
n, p = map(int, input().split())
buyers = [input().strip() for _ in range(n)][::-1]

next_a = 0
total = 0

for buyer in buyers:
    if buyer == 'halfplus':
        current_a = 2 * next_a + 1
    else:
        current_a = 2 * next_a
    total += (current_a * p) // 2
    next_a = current_a

print(total)
```

### Explanation
1. **Reading Input**: The input consists of the number of buyers `n` and the price per apple `p`, followed by `n` lines indicating whether each buyer received a half apple as a gift.
2. **Reversing Buyers List**: We reverse the list of buyers to simulate processing from the last buyer to the first.
3. **Reconstructing Apples Count**: For each buyer in reverse order:
   - If the buyer received a gift (`halfplus`), the number of apples before the sale is calculated as `2 * next_a + 1`.
   - If the buyer did not receive a gift (`half`), the number of apples before the sale is `2 * next_a`.
4. **Calculating Total Money**: For each reconstructed number of apples, we compute the money earned using integer division to ensure we handle fractional apples correctly, leveraging the fact that `p` is even. The total money is accumulated and printed at the end.

This approach efficiently reconstructs the sequence of apple counts and computes the total money using reverse iteration, ensuring accuracy and avoiding floating-point precision issues.
